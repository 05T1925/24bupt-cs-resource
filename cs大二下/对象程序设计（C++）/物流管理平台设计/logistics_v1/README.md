# 物流管理平台设计 logistics_v1

这是实验一的单机控制台版本，覆盖用户管理、管理员物流管理、快递发送/签收/查询、余额管理和文件持久化。

## 默认管理员

- 账号：`admin`
- 密码：`Admin0219`

首次运行会自动在 `data/` 目录下生成数据文件。
密码不会明文保存，`admin.txt` 中保存的是“用户名、姓名、随机盐、SHA-256 哈希、余额”。

## 编译运行

在项目根目录执行：

```bat
build.bat
```

然后运行：

```bat
run.bat
```

`run.bat` 会先切换到中文 Windows 常用的 936 控制台代码页，再启动 `bin\logistics_v1.exe`。`build.bat` 会同时刷新 `bin\logistics_v1.exe` 和 `src\main.exe`，两个程序入口使用同一份 `src/main.cpp` 编译生成。

当前版本源码文件保持 UTF-8 保存；编译时通过 `-finput-charset=UTF-8 -fexec-charset=GBK` 将字符串常量转换为中文 Windows 控制台更稳定的 GBK 字节。程序启动时会把标准输出接到 Windows Unicode 控制台写入逻辑，把 GBK 文本转换为 UTF-16 后显示，避免不同终端中中文菜单空白或乱码。直接运行 `src\main.exe` 或通过 `run.bat` 运行均可正常显示中文。

## 已实现的加分设计

- 终端页面式菜单和表格化查询结果。
- 完整类架构，业务逻辑不堆在 `main()` 中。
- 用户注册、登录、改密、充值、寄件、签收、查询。
- 普通用户查询快递时进行权限过滤，越权查询会写入日志。
- 密码使用随机盐 + SHA-256 哈希存储。
- 密码必须同时包含字母和数字。
- 所有交互输入均经过合法性验证，包括用户名、姓名、手机号、地址、密码、金额、菜单选项、物品描述、快递单号、查询时间、状态筛选和日志筛选条件。
- 发送快递提供样品描述快捷选项。
- 接收快递提供单个、批量、全部签收快捷选项。
- 余额不足时提供友好提示和立即充值入口。
- 所有关键操作写入 `data/operations.log`，管理员可筛选查看。
- 管理员可冻结/解冻用户，体现更完整的账号安全控制。
- 数据文件首次运行自动初始化。
- 启动时若发现数据文件存在格式异常行，会跳过异常行并写入日志，避免程序崩溃。
- 快递查询支持发件人、收件人、单号、时间范围、状态的组合筛选，并校验时间格式。
- 注册时检查手机号重复，寄件时禁止给自己寄件，进一步覆盖异常业务场景。

## 数据文件

- `data/users.txt`：普通用户数据。
- `data/admin.txt`：管理员数据。
- `data/expresses.txt`：快递数据。
- `data/operations.log`：系统操作日志。

程序会自动识别启动位置：从项目根目录、`bin/` 或 `src/` 启动时，都统一使用项目根目录下的 `data/`，避免生成多个混乱的数据目录。

## 说明

代码遵守实验一要求：除 `main` 外，业务辅助逻辑均实现为类成员函数；不改变对象状态的成员函数显式标注 `const`。
Windows 终端下程序启动时会自动初始化中文控制台环境；源码按 UTF-8 读取，字符串常量按 GBK 生成，显示时转换为 UTF-16 写入控制台，兼顾中文 Windows 的显示稳定性。

## 目录说明

- `src/`：源码目录，主要文件是 `main.cpp`，用于阅读、修改和重新编译程序。
- `bin/`：推荐运行目录，`logistics_v1.exe` 是编译生成的正式运行程序。
- `data/`：运行数据目录，保存用户、管理员、快递和日志数据；删除这些文本文件后，程序下次运行会重新初始化。

为了避免从 `src/` 或 `bin/` 手动双击时误以为数据没有同步，程序会统一识别项目根目录的 `data/` 作为有效数据目录，并把核心数据文件镜像到 `src/data/` 和 `bin/data/` 方便查看。实际业务读写以项目根目录 `data/` 为准。

## 当前输入校验覆盖

- 用户名：不能为空，长度必须为 3-20 位，只允许字母、数字、下划线，注册时还会检查重复和管理员保留名。
- 姓名：不能为空，不能包含控制字符，长度不能超过 30 个字符。
- 电话：必须为 11 位数字，注册时检查是否已被其他用户使用。
- 地址：不能为空，长度必须为 2-80 个字符，不能包含控制字符。
- 密码：长度必须为 6-30 位，必须同时包含字母和数字，不能包含空白字符，注册和改密都要求二次确认。
- 金额：必须为正数，最多保留两位小数，字母、负数、空字符串都会被拦截。
- 菜单、状态、编号：必须输入指定范围内的整数，越界和非数字会提示重输。
- 快递单号：可留空；非空时必须以 `EX` 开头，且只能包含字母和数字。
- 查询时间：可留空；非空时必须符合 `YYYY-MM-DD HH:MM:SS`，并检查真实年月日和时分秒范围。
- 日志筛选：结果只能填写 `SUCCESS`、`FAILED`、`DENIED` 或留空；操作人和操作类型关键字会检查长度和控制字符。
- 数据文件解析：启动加载时会拒绝格式不完整、余额/费用非法、状态字段非法的异常行，并把异常数量写入日志。
- 持久化失败处理：注册、改密、充值、寄件、签收、冻结/解冻等会检查核心数据保存结果；保存失败时提示错误并尽量回滚本次内存变更，避免提示成功但数据未落盘。

## 验收展示建议

建议按以下顺序演示，能覆盖功能检查和异常处理加分点：

1. 注册两个用户，演示用户名、手机号、密码规则校验。
2. 登录用户，展示顶部登录态、余额、未签收数量。
3. 充值后发送快递，展示物品描述快捷选项、扣费确认、规范快递单号。
4. 收件用户登录，展示未签收列表、单个/批量/全部签收快捷入口。
5. 用户查询快递，演示多条件筛选；再尝试查询他人单号，说明越权被过滤并写日志。
6. 管理员登录，查看用户、快递、操作日志，并按 `FAILED` 或 `DENIED` 筛选异常记录。
7. 管理员冻结用户，演示被冻结账号不能登录。

## 第二版推进方向

`logistics_v2` 建议在本版基础上重点体现继承、多态和角色扩展：

- 增加 `Courier` 快递员类及快递员登录菜单。
- 增加 `Item` 抽象基类，派生 `NormalItem`、`BookItem`、`FragileItem` 等，通过虚函数计算价格。
- 快递状态扩展为 `待揽收 -> 待签收 -> 已签收`。
- 用户寄件后先进入待揽收，管理员分配快递员，快递员揽收后进入待签收。
- 快递员获得部分快递费，管理员账户记录平台收入，形成更完整的资金流。
- 增加按快递员、物品类别、状态的组合查询，管理员可查看派送效率统计。
