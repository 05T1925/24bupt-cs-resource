## 7. 关键设计确认

### 7.1 协议帧格式

请求：

```text
REQ|command|token|argCount|arg1|arg2|...\n
```

响应：

```text
RES|1/0|code|message|recordCount|record1|record2|...\n
```

### 7.2 字段转义

```text
%  → %25
|  → %7C
\n → %0A
\r → %0D
```

未知或不完整转义序列抛出 ProtocolError。

### 7.3 安全限制

```text
MaxMessageLength = 8192
MaxFieldLength   = 1024
MaxVectorItems   = 256
```

### 7.4 TCP 半包/粘包处理

- 服务端：per-connection `std::string buffer`，`recv → buffer.append → while buffer contains '\n' → 提取帧 → decodeRequest`
- 客户端：`std::string receiveBuffer_`，`receiveFrame() → while no '\n' → recv → append → 超限抛 ProtocolError`
- 双边 sendAll：循环 send 直到全部发出

### 7.5 Token 零信任

- 登录成功：`sessions_.createSession(username, role)` 生成 SHA-256 token
- 后续请求：`sessions_.getSession(request.token, session)` 解析身份
- 所有业务命令使用 `session.username`，不使用客户端参数中的 username
- 客户端参数中的 username 仅用于：登录目标、注册目标、管理员操作对象、查询条件

### 7.6 并发保护

```text
CoreMutex / CoreLock     → LogisticsSystem 全局业务锁 (atomic_flag 自旋)
SessionMutex / SessionLock → SessionManager sessions_ 保护
```

修改型业务（REGISTER_USER / RECHARGE / SEND_EXPRESS / ASSIGN_COURIER / AUTO_ASSIGN_COURIER / AUTO_ASSIGN_ALL / PICKUP_EXPRESS / SIGN_EXPRESS / CREATE_COURIER / REMOVE_COURIER / SET_COURIER_FROZEN / CHANGE_PASSWORD / SET_USER_FROZEN）均在 CoreLock 内完成。

### 7.7 多线程连接模型

```text
主线程: accept → 创建 ClientThreadContext → CreateThread → CloseHandle → 继续 accept
worker thread: recv 循环 → 协议解析 → ServerController → sendAll → 断开时清理 session → closesocket
```

`--once` 模式保持单连接同步处理。

### 7.8 揽收事务一致性

```text
CoreLock 内:
  1. 校验 expressId 存在
  2. 校验 courier 可用
  3. 校验 express.courier == session.username
  4. 校验 status == WaitingPickup
  5. commission = fee * 0.5
  6. admin.balance -= commission
  7. courier.income += commission
  8. express.status = WaitingSign
  9. express.pickupTime = now
  10. saveAll() → 失败则恢复旧对象快照
  11. logger_.write(PICKUP_EXPRESS SUCCESS)
```

### 7.9 原子持久化

```text
StorageManager::saveLinesAtomically:
  1. 写 file.tmp
  2. 旧 file → file.bak
  3. file.tmp → file
  4. 失败时恢复 bak
```

### 7.10 日志哈希链

```text
seq|time|actorType|actor|action|result|detail|prevHash|currentHash
currentHash = SHA-256(seq|time|actorType|actor|action|result|detail|prevHash)
```

GENESIS 为初始 prevHash。VERIFY_LOG_CHAIN 逐条校验 seq 连续性 + prevHash 连续性 + currentHash 正确性。

### 7.11 登录安全

- 密码：SHA-256(salt + password)，每用户独立随机 salt
- USER/COURIER：failedCount >= 3 → 自动冻结 frozen=1
- ADMIN：记录失败次数但不自动冻结（handleAuthFailure freezeAllowed=false）
- 登录成功 → failedCount 清零
- auth_state.txt 持久化失败状态
