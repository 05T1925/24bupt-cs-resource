# v2_LOG00：Logistics_v2 启动规划日志

## 1. 已阅读材料

本次 V2 规划基于以下材料：

- `logistics_v1/LOG/v1_LOG00.md`
- `logistics_v1/LOG/v1_LOG01.md`
- `logistics_v1/LOG/v1_LOG_SUM.md`
- `实验(综合-物流管理平台设计)-面向对象程序设计与实践-2026春 发布版v3.docx`

实验文档确认：本作业必须提交三个独立程序，每个题目各一个程序，不能用最终网络版替代前两个程序。因此 `logistics_v2` 必须是独立目录和独立程序，同时体现为在 `logistics_v1` 基础上的功能增强。

## 2. V1 可继承资产

V1 已经完成以下能力，V2 应优先保留：

- 用户注册、登录、修改密码。
- 管理员登录、查看用户、查询快递、冻结/解冻用户、查看日志。
- 用户余额查询、充值、寄件、签收、组合查询。
- 密码 salt + SHA-256 哈希存储。
- 输入合法性集中校验。
- 普通用户权限过滤与越权日志。
- 文件持久化、异常行跳过和保存失败回滚。
- 页面式 CLI、快捷寄件描述、单个/批量/全部签收。
- Windows 中文控制台兼容方案。

V2 不应破坏这些已稳定能力。尤其不要重新设计中文编码层、不要让密码明文进入新文件、不要把业务逻辑堆回 `main()`。

## 3. 题目二强制需求

V2 必须新增：

- 快递员角色。
- 管理员添加和删除快递员。
- 用户登录时可以选择不同身份：用户、快递员、管理员。
- 快递分类：易碎品、图书、普通快递。
- 快递分类继承体系：物品基类与物品子类。
- 物品基类至少包含虚函数 `getPrice()`。
- 易碎品按 `8 元/kg` 计费。
- 图书按 `2 元/本` 计费。
- 普通快递按 `5 元/kg` 计费。
- 用户寄件后状态为待揽收，而不是 V1 的待签收。
- 管理员为待揽收快递分配快递员。
- 快递员查看自己名下未揽收快递。
- 快递员可选择一个或多个快递揽收。
- 揽收后状态从待揽收变为待签收。
- 揽收后管理员账户转出快递费 50% 给快递员账户。
- 收件用户签收待签收快递。
- 快递员查询自己的揽收和投递快递，可按发件人、收件人、时间、单号、状态筛选。
- 管理员查看全部用户、全部快递、全部快递员及其任务详情。
- 支持余额不足、非法输入等错误处理。

## 4. V2 核心设计方向

V2 建议保持 V1 的分层架构：

```text
实体类 + 仓储类 + 业务服务类 + UI 流程类 + 工具类
```

在此基础上新增：

- `Courier`：快递员实体。
- `CourierRepository`：快递员文件仓储。
- `ExpressItem`：物品抽象基类。
- `FragileItem`、`BookItem`、`NormalItem`：物品子类。
- `ExpressQueryCondition`：查询条件对象。
- `StorageManager`：原子保存与备份恢复。
- `AuditLogger` 或增强版 `Logger`：日志哈希链。

## 5. V2 状态流转

```text
用户寄件 -> 待揽收
管理员分配快递员 -> 仍为待揽收，但 courier 字段不为空
快递员揽收 -> 待签收
收件人签收 -> 已签收
```

业务层必须兜底校验：

- 未分配快递员的快递不能被快递员揽收。
- 快递员不能揽收不属于自己的快递。
- 用户不能签收待揽收快递。
- 用户不能签收别人的快递。
- 已签收快递不能重复签收。

## 6. 推荐加分优化

优先级从高到低：

1. 多态计费真实落地：寄件流程实际调用 `ExpressItem::getPrice()`。
2. 原子化保存：`.tmp -> .bak -> 正式文件`，减少文件损坏风险。
3. 日志哈希链：管理员可校验日志完整性。
4. 持久化登录失败次数：连续失败 3 次自动冻结账号。
5. 查询条件对象化：避免参数列表继续膨胀。
6. 快递员任务统计：收入、待揽收数、已揽收数、已完成数。
7. 中英文混合表格宽度估算：提升 CLI 观感。

## 7. 首轮实施建议

第一轮不要急着加入所有加分项。先跑通题目二业务闭环：

```text
Courier + CourierRepository
ExpressStatus 三状态
Express 新增 courier/pickupTime/itemType/itemAmount
ExpressItem 多态计费
用户寄件进入待揽收
管理员分配快递员
快递员揽收
收件人签收
管理员和快递员查询
```

闭环跑通后，再补原子保存、日志哈希链、统计和测试。
