# V2 开发路线图

## Phase 0：建立独立项目

目标：

- `logistics_v2` 与 `logistics_v1` 分离。
- 保留 V1 稳定代码作为 V2 基线。

任务：

- 复制 V1 的 `src/main.cpp`、`build.bat`、`run.bat`。
- 修改程序标题、二进制名和 README。
- 确认 `data/` 使用 V2 目录。
- 编译并验证主菜单中文正常。

验收：

- V2 可独立编译运行。
- 不依赖 V1 数据目录。

## Phase 1：状态与快递字段扩展

目标：

- 快递状态从两状态改为三状态。
- `Express` 支持快递员、揽收时间、物品类型、数量/重量。

任务：

- 扩展 `ExpressStatus`。
- 修改 `Express::statusName()`。
- 修改 `Express::serialize()` / `deserialize()`。
- 修改寄件后初始状态为 `WaitingPickup`。
- 修改签收逻辑，只允许 `WaitingSign`。

验收：

- 用户寄件后显示待揽收。
- 用户不能签收待揽收快递。

## Phase 2：多态物品计费

目标：

- 让实验要求中的继承和虚函数真实落地。

任务：

- 新增 `ExpressItem` 抽象基类。
- 新增 `FragileItem`、`BookItem`、`NormalItem`。
- 新增 `ExpressItemFactory` 或静态创建函数。
- 寄件流程选择类型和输入重量/册数。
- `sendExpress()` 调用 `getPrice()` 计算费用。

验收：

- 易碎品、图书、普通快递费用不同。
- 余额不足时按实际费用提示。
- 数据文件保存类型、数量/重量和费用。

## Phase 3：快递员实体与登录

目标：

- 支持快递员账号持久化和登录。

任务：

- 新增 `Courier`。
- 新增 `CourierRepository`。
- 新增 `couriers.txt`。
- 管理员新增快递员。
- 快递员登录。
- 快递员查看收入。

验收：

- 管理员可创建快递员。
- 快递员密码使用 salt + SHA-256。
- 冻结快递员不能登录。

## Phase 4：分配与揽收闭环

目标：

- 跑通题目二最重要业务链路。

任务：

- 管理员查看待揽收快递。
- 管理员为快递分配快递员。
- 快递员查看自己名下待揽收任务。
- 快递员单个、批量、全部揽收。
- 揽收后状态改为待签收。
- 管理员账户转 50% 到快递员账户。

验收：

- 快递员不能揽收他人任务。
- 已揽收快递不能重复揽收。
- 管理员余额和快递员收入变化正确。

## Phase 5：查询与权限完善

目标：

- 三类身份查询都符合权限边界。

任务：

- 新增 `ExpressQueryCondition`。
- 重构用户查询、管理员查询。
- 新增快递员任务查询。
- 管理员按快递员查看任务。
- 查询支持状态和物品类型。

验收：

- 普通用户无法看无关快递。
- 快递员无法看其他快递员任务。
- 管理员能查看全局数据。

## Phase 6：加分项增强

目标：

- 提升工程可靠性和验收亮点。

任务：

- 原子化保存与 `.bak` 备份。
- 日志哈希链与完整性校验。
- 登录失败次数持久化，三次失败自动冻结。
- 中英文混合表格宽度优化。
- 任务统计：按快递员、状态、物品类型、时间统计。

验收：

- 保存失败不会提示假成功。
- 日志被手动篡改后能检测。
- 管理员可以查看统计结果。

## Phase 7：测试与报告材料

目标：

- 为验收和实验报告准备证据。

任务：

- 写 `tests/V2_TEST_CASES.md`。
- 写 `LOG/v2_LOG01.md` 记录实现过程。
- README 写清编译运行方式、默认账号、功能说明。
- 整理类设计说明和关键问题解决方案。

建议测试链路：

1. 注册两个用户并充值。
2. 管理员创建快递员。
3. 用户寄普通、图书、易碎品三类快递。
4. 管理员分配快递员。
5. 快递员批量揽收。
6. 收件人批量签收。
7. 三种身份分别查询。
8. 演示余额不足、越权查询、非法输入、重复揽收、重复签收。
