# Java 小作业二初步计划

## 1. 作业总体理解

本次小作业包含多个相对独立的 Java 编程任务，主要覆盖以下知识点：

- 多线程创建、终止、重启与线程间共享变量
- 多线程同步、`wait()` / `notifyAll()`、生产者消费者模型
- 多线程分段计算与结果汇总
- 文件系统递归复制
- Web 服务器配置与 JSP 页面
- Swing 图形界面、`GridBagLayout` 布局与事件处理
- Java 泛型、比较器设计、组合对象排序

建议将每个题目做成相对独立的小程序，避免所有功能混在一个主类中。这样便于调试、提交、写报告，也方便分阶段生成提示语。

### 阶段二：Watchdog 线程监控

对应题目：

- A 线程执行主要工作，定期设置 `watchdog = 1`
- B 线程定期检查 watchdog
- 连续 10 次读到 0 判定 A 出错
- B 线程报警，并重启 A 线程

关键分析：

- 共享变量需要线程可见性，可以使用 `volatile int watchdog` 或 `AtomicInteger`。
- 不建议使用 `Thread.stop()`，应使用中断或运行标志停止 A 线程。
- “先杀掉原来 A 线程”在作业语境中可解释为通知原 A 线程退出，然后创建新的 A 线程对象。
- 为了演示重启，可以让 A 线程在运行一段时间后模拟故障，不再设置 watchdog。

需要 Gemini 提供的详细提示语方向：

- 如何在不使用危险 API 的情况下体现“杀掉并重启 A 线程”。
- 如何设计演示输出，让老师能看到正常心跳、连续失败、报警、重启全过程。
- 是否使用 `AtomicInteger`、`volatile`、`interrupt()` 的组合。

可喂给 Gemini 的提示语草案：

```text
请为 Java 小作业 Watchdog 多线程题生成一段高质量 Codex 提示语。题目要求：A 线程执行主要工作，并每 3 秒把 watchdog 变量置为 1；B 线程每 2 秒检查 watchdog，如果为 1 就改为 0，如果连续 10 次读到 0 就认为 A 出错，打印报警，并先结束原 A 线程，再创建新的 A 线程对象启动。要求使用 Java 标准库，避免 Thread.stop()，通过 interrupt 或运行标志安全停止线程。请给出建议类结构、关键变量、演示故障的方法、输出格式和测试步骤。
```

### 阶段三：仓库多线程同步

对应题目：

- 三个仓库，每个容量为 20
- 两个 fetch 线程，一个 save 线程
- 每次存取 1 到 5 个单位
- `save` 选择库存最少的仓库存放
- `fetch` 选择库存最多的仓库取出
- 不满足条件时等待
- 输入一行代表一次操作
- 成功操作后打印当前库存和本次操作内容

关键分析：

- 不能分别对三个仓库对象连续调用 `wait()`。
- 应使用一个统一锁管理三个仓库的库存状态。
- 等待条件应写在 `while` 循环中，避免虚假唤醒。
- 每次成功操作后调用 `notifyAll()`，唤醒可能可以继续执行的线程。
- 输入分发可以有两种实现：
  - 简化版：主线程读输入后直接调用同步方法，方法内部代表对应线程操作。
  - 更贴题版：三个工作线程各有一个任务队列，主线程只负责把输入命令分发给对应线程。

初步建议：

- 为了更贴合“fetch 线程和 save 线程读取每次存取信息”，建议使用三个 `BlockingQueue<Integer>`。
- `fetch1`、`fetch2`、`save` 三个线程从各自队列取数量，然后调用统一的 `WarehouseManager`。
- `WarehouseManager` 内部使用 `synchronized(lock)`、`wait()`、`notifyAll()`。

需要 Gemini 提供的详细提示语方向：

- 采用简化版还是更贴题版。
- 如何解释禁止连续 `warehouse1.wait()`、`warehouse2.wait()`、`warehouse3.wait()` 的原因。
- 如何设计输入结束方式，例如输入 `q` 或 EOF。
- 如何打印清晰日志。

可喂给 Gemini 的提示语草案：

```text
请为 Java 小作业“三个仓库、两个 fetch 线程、一个 save 线程”生成详细 Codex 提示语。题目要求：三个仓库容量均为 20；fetch1、fetch2 每次取 1-5 个单位，选择库存最多的仓库取，如果库存不足则 wait；save 每次存 1-5 个单位，选择库存最少的仓库存，如果会溢出则 wait；库存相等任选；输入 1 3 表示 fetch1 取 3，2 3 表示 fetch2 取 3，3 3 表示 save 存 3；每次成功后打印本次操作和三个仓库库存。要求绝对不能连续写 warehouse1.wait(); warehouse2.wait(); warehouse3.wait(); 请在提示语中要求使用统一锁、while 判断条件、notifyAll，并解释为什么不能对三个仓库分别 wait。代码风格适合 Java 课程作业。
```

### 阶段五：泛型组合排序

对应题目：

- 类 A 的对象存储在 `A[] arra`
- 类 B 的对象存储在 `B[] arrb`
- 同一下标的 `arra[i]` 和 `arrb[i]` 组成一个被排序组合
- 编写 `comparecouple` 比较两个组合大小
- 编写 `sortcouple` 对整个数组排序
- 要支持泛型，适用于不同类组合

关键分析：

- 题目中“类 B 的多个对象存储在 `A[] arrb`”疑似笔误，应按 `B[] arrb` 理解。
- 排序时必须同步交换 `arra` 和 `arrb`，不能只排序其中一个数组。
- 比较规则应由外部传入，才能真正泛型化。

初步接口设计：

```java
interface CoupleComparator<A, B> {
    int compare(A a1, B b1, A a2, B b2);
}
```

排序方法：

```java
public static <A, B> void sortCouple(A[] arra, B[] arrb, CoupleComparator<A, B> comparator)
```

需要 Gemini 提供的详细提示语方向：

- 是否命名为 `comparecouple` / `sortcouple`，还是遵循 Java 驼峰命名 `compareCouple` / `sortCouple`。
- 示例类 A、B 如何设计，比较规则如何展示。
- 用冒泡排序更适合作业展示，还是使用 `Arrays.sort()` 包装下标。

可喂给 Gemini 的提示语草案：

```text
请为 Java 小作业“泛型组合排序”生成详细 Codex 提示语。题目要求：A[] arra 和 B[] arrb 中相同下标的对象组成一个组合，例如 arra[1] 和 arrb[1] 是一个组合；编写 comparecouple 比较两个组合大小，再编写 sortcouple 按 comparecouple 规则对整个组合数组排序；要求支持泛型，适用于不同类型组合。请设计简单清晰的泛型接口、排序方法和演示类，排序时必须同步交换两个数组，保证组合关系不变。代码风格适合 Java 初学作业，并保留题目要求的方法名或说明命名处理。
```

## 5. 后续协作方式

建议后续按阶段推进：

1. 将本计划中的某一阶段提示语发给 Gemini。
2. 让 Gemini 输出更细、更具体的 Codex 提示语。
3. 将 Gemini 生成的提示语发回给 Codex。
4. Codex 根据提示语生成代码、运行测试、修改问题。
5. 每完成一阶段，再进入下一阶段。

这样做的好处是每一轮目标清晰，不容易把多个线程题、GUI 题和 JSP 环境混在一起。
