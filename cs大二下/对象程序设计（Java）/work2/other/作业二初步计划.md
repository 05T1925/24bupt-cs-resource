# 2026 小作业二初步计划

> 用途：本文档用于先梳理作业要求、拆分实现阶段，并为后续向 Gemini 分阶段索取详细提示语提供材料。当前版本只作为初步计划，后续可根据老师要求、运行环境、代码风格要求继续细化。

## 一、作业总体理解

本次作业主要围绕 Java 面向对象程序设计中的综合实践展开，覆盖以下内容：

1. 多线程监控与线程重启。
2. 多线程分段求和。
3. `wait` / `notifyAll` 线程通信与仓库同步。
4. 递归复制目录和文件。
5. Web 服务器配置与 JSP 页面。
6. Swing 图形界面、`GridBagLayout` 布局与事件处理。
7. 泛型方法、组合比较与同步排序。
8. 选做：天气预报信息获取与显示。

从难度和风险看，重点不在语法本身，而在：

- 多线程共享变量的可见性。
- `wait()` 必须在正确锁对象上调用。
- 多线程程序不能靠固定 `sleep` 硬凑结果。
- GUI 布局要尽量贴近题图。
- 泛型排序要保持两个数组同下标对象的组合关系。
- JSP 部分需要明确 Tomcat 或其他 Web 服务器环境。

### 阶段 2：实现基础多线程题

对应题目：

- 题 1：Watchdog 监控与 A 线程重启。
- 题 2：10 个线程分段求和。

实现重点：

- 题 1 使用 `volatile` 或 `AtomicInteger` 保证 watchdog 变量可见。
- A 线程通过中断标志安全退出，不使用已废弃且危险的 `Thread.stop()`。
- B 线程连续 10 次读到 0 后打印报警，并创建新的 A 线程对象。
- 题 2 每个线程负责一个固定区间，主线程用 `join()` 等待全部完成。
- 如果需要共享总和，使用 `AtomicInteger`、同步块，或先保存局部和再汇总。

风险点：

- 如果 A 线程被“杀掉”的实现过于粗暴，可能被认为不规范。
- 如果没有等待 10 个线程全部结束就输出，结果可能不完整。

可发给 Gemini 的提示语：


### 阶段 3：实现仓库同步题

对应题目：

- 题 3：三个容量为 20 的仓库，两个 fetch 线程，一个 save 线程。

实现重点：

- 用一个统一的管理类保存三个仓库库存，例如 `int[] stocks = new int[3]`。
- 用一个统一锁对象控制所有仓库状态，不能分别对三个仓库连续调用 `wait()`。
- `save` 每次选择库存最少的仓库；如果所有可选操作都会溢出，则等待。
- `fetch` 每次选择库存最多的仓库；如果库存最多的仓库也不够取，则等待。
- 操作成功后打印本次操作和当前库存，并调用 `notifyAll()`。
- 输入命令根据第一列分发给 `fetch1`、`fetch2`、`save`。

关于禁止连续写 `warehouse1.wait(); warehouse2.wait(); warehouse3.wait();` 的分析：

- `wait()` 必须在持有对应对象监视器的 `synchronized` 块中调用。
- 一个线程不可能通过连续等待多个仓库对象来正确表达“等待任一仓库状态变化”。
- 多锁等待容易导致死锁、遗漏通知、状态判断不一致。
- 正确做法是把“三个仓库的整体库存状态”作为一个共享条件，用同一个锁保护。

可发给 Gemini 的提示语：

```text
请为 Java 多线程仓库同步题提供详细实现方案和代码提示。

题目要求：有三个容量为 20 的仓库，两个 fetch 线程和一个 save 线程。每次存取 1 到 5 个单位。save 线程选择货物最少的仓库存放货物，如果仓库会溢出则进入 wait 状态；fetch 线程选择货物最多的仓库取货，如果该仓库取空还不够则进入 wait 状态。如果 2 到 3 个仓库库存相等则任选一个操作。输入格式为一行一个操作，例如 1 3 表示 fetch1 取 3 个单位，2 3 表示 fetch2 取 3 个单位，3 3 表示 save 存 3 个单位。每次成功操作后打印当前库存及本次操作内容。

请重点解释为什么不能连续写 warehouse1.wait(); warehouse2.wait(); warehouse3.wait(); 并给出正确的 wait/notifyAll 设计。要求使用一个统一锁管理三个仓库状态，代码适合学生作业提交。
```

### 阶段 7：实现泛型组合排序

对应题目：

- 题 7：`comparecouple` 与 `sortcouple` 泛型组合排序。

实现重点：

- 两个数组 `A[] arra` 和 `B[] arrb` 中，同一下标对象组成一个组合。
- 排序时比较的是组合，不是单独的 A 或 B。
- 交换时必须同时交换 `arra[i]` 和 `arrb[i]`。
- 为了支持各种类组合，需要引入泛型比较器接口。

建议接口：

```java
interface CoupleComparator<A, B> {
    int compare(A a1, B b1, A a2, B b2);
}
```

建议方法：

```java
public static <A, B> int compareCouple(
    A a1, B b1,
    A a2, B b2,
    CoupleComparator<A, B> comparator
)

public static <A, B> void sortCouple(
    A[] arra,
    B[] arrb,
    CoupleComparator<A, B> comparator
)
```

可发给 Gemini 的提示语：

```text
请为 Java 泛型组合排序作业生成详细实现方案和代码。题目要求编写 comparecouple 方法，对类 A 对象 a 和类 B 对象 b 的组合比较大小；A 的多个对象存储在 A[] arra 中，B 的多个对象存储在 B[] arrb 中，两个数组同一下标位置的对象组成一个被排序的组合，例如 arra[1] 和 arrb[1] 是一个组合。还要编写 sortcouple 方法，对整个数组按照 comparecouple 规定的大小排序。两个方法都要求支持泛型，从而支持各种不同类的组合。

请设计一个泛型比较器接口，并实现 compareCouple 和 sortCouple。排序时必须保持 arra 和 arrb 的同下标组合关系同步交换。请给出示例类 A、B，示例比较规则，以及完整测试代码。
```
