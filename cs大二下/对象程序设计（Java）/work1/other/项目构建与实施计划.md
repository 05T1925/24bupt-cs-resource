#### ArrayCopyDemo（Q1.1）

```

核心方法：

│   └── 步骤6：打印 4 种结果对比

关键注释：
    // copyOfRange(src, 2, 5) 复制索引 [2, 5)，即 index 2, 3, 4

```

```
│   ├── 方式2：selectionSort(arrCopy2) + 计时
```

#### Instrument.java 详细规格

```java
public abstract class Instrument {
    protected int no;                          // 全局编号（所有乐器统一编号）
    protected String name;                     // 乐器姓名
    private static int instrumentCount = 0;    // 全局计数器

    public Instrument(String name) {
        this.name = name;
        this.no = ++instrumentCount;           // 每次构造自动递增
    }

    public int getNo() { return no; }
    public String getName() { return name; }

    public abstract void play();               // 抽象：各乐器演奏

    public void tune() {                       // 具体方法
        System.out.println("正在调音...");
    }
}
```

#### 子类详细规格（以 Guitar 为例，Piano / Violin 同理）

```java
public class Guitar extends Instrument {
    private int guitarNo;                      // 吉他独立编号（仅 Guitar 内计数）
    private static int guitarCount = 0;        // 吉他独立计数器

    public Guitar(String name) {
        super(name);                           // 触发父类构造器 → 全局编号递增
        this.guitarNo = ++guitarCount;         // 吉他编号独立递增
    }

    @Override
    public void play() {
        System.out.println("吉他 " + getName() + " 发出悠扬的弦音~");
    }

    @Override
    public String toString() {
```

## 三、技术难点与避坑指南

### 🔴 难点一（Q4）：父类与子类独立计数的 `no` 属性（核心难点）

**问题本质**：Java 中 `static` 字段属于类而非实例，且不会被子类"覆盖"。这是一个利用 `static` 字段类级别隔离特性的经典设计题。

**避坑清单**：

| 坑 | 错误做法 | 正确做法 |
|----|---------|---------|
| 只在父类写 static | 子类共用同一计数器，无法独立 | 父类有自己的 `instrumentCount`，子类也有自己的 `xxxCount` |
| 在子类中重新定义与父类同名的 static 字段 | 会"隐藏"（hide）父类字段，造成混淆 | 子类用不同变量名（如 `guitarCount`），并在自己构造器中递增 |
| 试图 override static 方法/字段 | Java 不支持 static 方法/字段的 override | 理解 hide vs override 的区别 |
| 构造器链顺序搞错 | 先递增子类计数器再调用 super() | 先 super(name) 触发父类计数，再递增子类计数 |
| toString 中混淆 no 来源 | 直接打印 `no`，不清楚是哪个 no | 明确：`no` 继承自父类（全局编号），`xxxNo` 是子类自己的 |

**static 计数器记忆口诀**：
> "父类一个 static，所有子类共享；子类各自一个 static，各管各的账。"

---

### 🔴 难点二（Q1.7）：二维数组整体排序

**问题分析**：

题目要求 `arr[0]` 的所有元素 ≤ `arr[1]` 的所有元素 ≤ ... ≤ `arr[9]` 的所有元素。本质是把所有元素当作一个整体从小往大排。

**为什么 `Arrays.sort(int[][])` 不能用？**
- `Arrays.sort(int[][])` 按**整行**排序——它将 `arr[0]` 到 `arr[9]` 视作 10 个 `int[]` 对象，比较的是 `int[].hashCode()` 或者数组引用，而不是元素值。
- 这会导致"按行排序"而非"按元素排序"。

**正确做法（三步法）**：

```
二维数组 (10×10)
       │
       ▼ System.arraycopy 逐行拷贝
一维数组 (长度100)
       │
       ▼ Arrays.sort() ← 这里可以用 sort 了！
排序后的一维数组
       │
       ▼ System.arraycopy 逐行回填
排序后的二维数组 (10×10)
```

**关键代码思路**：

```java
// 展平：二维 → 一维
int[] flat = new int[rows * cols];
for (int i = 0; i < rows; i++) {
    System.arraycopy(matrix[i], 0, flat, i * cols, cols);
}
// 排序
Arrays.sort(flat);
// 回填：一维 → 二维
for (int i = 0; i < rows; i++) {
    System.arraycopy(flat, i * cols, matrix[i], 0, cols);
}
```

**验证方法**：排序后遍历检查——`matrix[0][9]`（第一行最大值）≤ `matrix[1][0]`（第二行最小值）。

### 🟡 难点三（Q3）：`instanceof` + 向下转型

**`instanceof` 使用模式**（标准范式）：

```java
// 模式1：先判断再转型（推荐，安全）
if (character instanceof Warrior) {
    Warrior w = (Warrior) character;      // 安全转型
    w.shieldBlock();
}

// 模式2：Java 16+ 模式匹配（如果你的环境支持）
if (character instanceof Warrior w) {
    w.shieldBlock();  // 无需手动转型
}

// 模式3：先判断再直接调用（紧凑写法）
if (character instanceof Warrior) {
    ((Warrior) character).shieldBlock();
}
```

**直接强转的风险**：
```java
// ❌ 危险：如果 character 实际是 Mage，抛 ClassCastException
((Warrior) character).shieldBlock();
```

### 🟡 难点四（Q6）：接口变量无法调用接口外方法

**问题场景复现**：
```java
Walkable w = new Amphibian("青蛙");
w.walk();   // ✅ 编译通过
w.swim();   // ❌ 编译失败！Walkable 接口没有 swim()
w.jump();   // ❌ 编译失败！Walkable 接口没有 jump()
```

**原因**：Java 是静态类型语言，编译器按**变量声明类型**（`Walkable`）检查方法调用，而非运行时实际类型（`Amphibian`）。

**解决方案对比**：

| 方案 | 代码 | 安全性 | 推荐度 |
|------|------|:---:|:---:|
| 向下转型 | `((Amphibian) w).jump()` | 需确保类型匹配 | ⭐⭐⭐ |
| instanceof 守卫 | `if (w instanceof Amphibian a) a.jump()` | 安全 | ⭐⭐⭐⭐⭐ |
| 反射 | `w.getClass().getMethod("jump").invoke(w)` | 编译不检查 | ⭐（仅了解） |

### 🟡 难点五（Q7）：异常自动重启设计

**基本框架**：
```java
public static void runWithAutoRestart() {
    int maxRetries = 3;  // 可选：最大重试次数
    int retryCount = 0;

    while (retryCount < maxRetries) {
        try {
            doWork();
            break;  // 成功 → 退出
        } catch (Exception e) {
            retryCount++;
            System.err.println("异常: " + e.getMessage());
            if (retryCount < maxRetries) {
                System.err.println("正在重启...（第" + retryCount + "次重试）");
            } else {
                System.err.println("已达最大重试次数，程序退出。");
                throw new RuntimeException("任务失败", e);
            }
        }
    }
}
```

**设计要点**：
- 最大重试次数 —— 避免死循环
- 异常日志 —— 便于排查
- 状态重置 —— 重试前清理脏数据

| 算法 | 时间复杂度 | 空间复杂度 | 稳定性 | 特点 |

- 使用 `System.nanoTime()` 计时（精度高于 `currentTimeMillis()`）

### 🟢 难点七（Q8）：Checked vs Unchecked Exception

**记忆表格**：

| 维度 | Checked Exception | Unchecked Exception |
|------|:---:|:---:|
| 父类 | `Exception`（非 RuntimeException） | `RuntimeException` |
| 编译器检查 | ✅ 强制处理 | ❌ 不强制 |
