# 计算机网络实验二执行规划（2026）

## 1. 官方要求摘要

### 1.1 实验目标

实验由 1 人独立完成，使用联网计算机和 Wireshark 捕获并分析：

1. DHCP 报文及动态地址分配过程。
2. ICMP 报文格式及主要字段。
3. IPv4 数据报分片结构。
4. TCP 建立连接、数据通信和释放连接过程。

依据：

- `Lab2-PacketAnalysis-2026.pdf` 第 2、3、7 页。
- `计算机网络实验二指导书.pdf` 第 3、4 页。

### 1.2 报告必须覆盖的内容

1. 标准实验报告封面，格式与实验一相同。
2. 实验内容和实验环境。
3. 每类报文的捕获方法、操作过程和真实捕获结果。
4. DHCP 通信过程。
5. ICMP 报文格式及主要字段功能。
6. IP 分片原理，以及所有分片的包长度、DF、Identification、MF、Fragment Offset。
7. TCP 建立与释放连接的消息序列图，以及 SYN、ACK、FIN、Seq、Ack 的真实值。
8. 实验中遇到的问题、解决方法、总结和心得。

依据：

- `Lab2-PacketAnalysis-2026.pdf` 第 7、8 页。
- `计算机网络实验二指导书.pdf` 第 4、5 页。

### 1.3 提交要求

- 截止时间：2026 年 6 月 26 日。
- 平台：北邮教学云平台 `ucloud.bupt.edu.cn`。
- 文件格式：PDF。
- 文件名：`计网实验2报告-3位班级号-学号-姓名.pdf`。

依据：`Lab2-PacketAnalysis-2026.pdf` 第 8 页。

## 2. 数据真实性与证据链

以下规则贯穿全部阶段：

1. 协议字段必须来自真实 `.pcapng`、TShark CSV 或 Wireshark 截图。
2. 所有关键表格保留 `frame.number`，并注明来源抓包。
3. 不用理论值替代实际字段；理论计算只用于验证一致性。
4. 不混用不同抓包、不同 DHCP 事务或不同 `tcp.stream`。
5. 缺少关键报文时标为 `WARN` 或 `FAIL`，必要时重抓，不补写数据。
6. 每次正式抓包记录接口、命令、过滤器、时间、SHA-256、CSV 行数、关键帧和验收结果。
7. 截图必须来自最终采用的真实抓包，显示 Frame Number、包列表和关键协议字段。

## 4. 优化后的执行顺序

### 阶段 A：恢复检查与截图补拍

目标：确保环境证据和 DHCP 截图可直接用于最终报告。

步骤：

1. 读取 `PROJECT_STATE.md`、`PROJECT_EXECUTION_BASELINE.md` 和 `NEXT_CHAT_HANDOFF_STAGE3.md`。
2. 运行 `tshark -D`，按名称和 GUID 重新确认 WLAN。
3. 复拍 Wireshark/TShark 版本、接口列表、`ipconfig /all` 和 Wireshark 的 WLAN 选择界面。
4. 打开当前 `captures/dhcp.pcapng`，使用 `dhcp || bootp`。
5. 对 Frame 1 至 Frame 5 复拍无提示截图，不重新抓 DHCP。
6. 更新截图审计结果。

验收：

- 环境图能证明版本、WLAN 名称/GUID 和实际网络配置。
- DHCP 截图与当前 pcap 的 Frame 1 至 Frame 5 一致。
- 截图中无助手提示、悬浮标记或错误接口。

### 阶段 B：ICMP 捕获与分析

目标：捕获至少一组可匹配的 IPv4 Echo Request/Reply。

建议操作：

1. 正式抓包前重新确认 WLAN。
2. Wireshark 不设捕获过滤器，或使用 `icmp`。
3. 依次尝试：
   - `ping -4 -n 4 www.bupt.edu.cn`
   - `ping -4 -n 4 114.114.114.114`
   - `ping -4 -n 4 10.21.128.1`
4. 保存为 `captures/icmp.pcapng`。
5. 导出 `exports/icmp_fields.csv`。
6. 按 Identifier、Sequence、反向源/目的地址匹配请求与响应。
7. 生成 `exports/icmp_analysis.md`。
8. 通过字段校验后再截图。

重点字段：

- Frame、时间、源/目的 IP、TTL、IP Protocol。
- ICMP Type、Code、Checksum、Identifier、Sequence Number、数据长度。

验收：

- 至少一组 Echo Request/Reply 匹配成功。
- Type 8 与 Type 0、Identifier 和 Sequence 可回查。
- CSV、分析文件和至少 4 张截图齐全。

### 阶段 C：IPv4 分片捕获与分析

目标：获得同一原始 IPv4 数据报的一组完整分片。

建议操作：

1. 不设置捕获过滤器，避免漏掉首片或末片。
2. 优先运行 `ping -4 -n 1 -l 8000 <目标>`。
3. 目标依次尝试默认网关、`114.114.114.114`、学校站点。
4. 若未形成分片，再尝试 4000 或 2000 字节，并记录实际命令。
5. 保存为 `captures/ip_fragment.pcapng`。
6. 使用 `ip.flags.mf == 1 || ip.frag_offset > 0` 筛选。
7. 导出 `exports/ip_fragment_fields.csv`。
8. 按源 IP、目的 IP、协议和 Identification 分组。
9. 校验偏移连续性、MF 和最后一片。
10. 生成 `exports/ip_fragment_analysis.md`，通过后截图。

重点字段：

- Frame、Total Length、Identification、DF、MF、Fragment Offset、Protocol。

验收：

- 同一 Identification 至少有多个分片。
- 至少一片 `MF=1`。
- 最后一片 `MF=0` 且 Offset 大于 0。
- 按 8 字节单位换算后无明显缺口或重叠。
- CSV、分析文件和至少 5 张截图齐全。

### 阶段 D：TCP 建连与释放捕获

目标：在同一 `tcp.stream` 中获得完整三次握手和正常 FIN 释放。

建议操作：

1. 捕获过滤器使用 `tcp port 80`。
2. 执行：
   - `curl.exe -4 -v --http1.1 -H "Connection: close" http://example.com/ -o NUL`
   - 失败时改用 `http://neverssl.com/`
3. curl 退出后继续捕获约 5 秒。
4. 保存为 `captures/tcp.pcapng`。
5. 导出相对序号和原始序号 CSV。
6. 按 `tcp.stream` 分组，选择最完整的一条流。
7. 生成握手表、释放表和 `exports/tcp_sequence.mmd`。
8. 生成 `exports/tcp_analysis.md`，通过后截图。

重点字段：

- Frame、IP/端口、Stream、Flags、SYN、ACK、FIN、RST、Seq、Ack、Len。

验收：

- 同一流中存在 SYN、SYN+ACK、ACK。
- 优先要求正常 FIN 释放；只有 RST 时应重抓。
- Seq/Ack 关系与实际报文一致。
- 序列图方向和主动关闭方符合真实抓包。
- CSV、分析、序列图和至少 8 张截图齐全。

### 阶段 E：综合校验和报告初稿

步骤：

1. 对四个正式 pcap 重新计算 SHA-256。
2. 重新运行全部字段导出和综合校验。
3. 刷新 `exports/analysis_summary.md`，清除旧 DHCP 摘要。
4. 建立报告字段来源表，逐项关联 pcap、CSV、Frame 和截图。
5. 生成 `report/draft.md`。
6. 报告按 DHCP、ICMP、IP 分片、TCP 四章组织。
7. TCP 序列图导出为可插入报告的图片。
8. 缺少个人信息时保留 `【待填写】`，不生成最终文件名。

验收：

- 四类协议章节均有捕获方法、真实字段表、协议解释和截图。
- 每个关键表格包含 Frame Number。
- “理论说明”与“实际捕获结果”分开写。
- 问题与解决方法来自真实执行记录。

### 阶段 F：DOCX/PDF 与最终提交检查

步骤：

1. 获取 3 位班级号、学号、姓名和实验日期。
2. 套用与实验一一致的标准封面。
3. 生成 DOCX，并逐页检查图片、表格和分页。
4. 导出 PDF。
5. 搜索 `TODO`、`待填写`、`实际值`、示例值和未替换的序列图占位符。
6. 从 PDF 中抽查所有关键数值，对照 CSV 和 pcap。
7. 生成 `report/final_checklist.md`。
8. 按规范重命名并准备上传。

最终验收：

- PDF 可正常打开，封面完整，图片清晰，表格不溢出。
- 无提示语、占位符、错误帧号或过期 DHCP 数据。
- 文件名严格为 `计网实验2报告-3位班级号-学号-姓名.pdf`。
- 在 2026 年 6 月 26 日前上传至北邮教学云平台。

## 6. 关键风险与处理

| 风险 | 处理策略 |
|---|---|
| WLAN 接口编号变化 | 每次抓包前按名称和 GUID 核对，不只看编号 |
| ICMP 目标不响应 | 依次改用公共 DNS 和默认网关 |
| 大包未产生可见分片 | 更换目标/网络，调整长度，检查卸载影响 |
| TCP 80 被拦截或自动跳转 HTTPS | 使用明确 HTTP URL，必要时切换网络 |
| 只有 TCP RST，没有 FIN | 使用 `Connection: close`，延迟停止，重新抓包 |
| 截图与最终 pcap 不一致 | 先完成 CSV 验收，再按确定帧号截图 |
| 报告引用旧 DHCP 数据 | 当前 DHCP 以正式 pcap 和 CSV 为准，最后刷新综合摘要 |
| PDF 排版错乱 | 先生成 DOCX，逐页视觉检查后再导出 PDF |
