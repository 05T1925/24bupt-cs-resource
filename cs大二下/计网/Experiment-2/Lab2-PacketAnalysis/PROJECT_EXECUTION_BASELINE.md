## 1. 不可违反的原则

1. 所有实验字段必须来自真实 `pcapng`、TShark CSV 或 Wireshark 截图。
2. 每个关键字段表必须保留 `frame.number`，并注明源抓包文件。
3. 不用理论计算值替代实际字段值；理论计算只用于一致性校验。
4. 缺少关键报文时标记 `FAIL/WARN` 并重抓，不补写或推测数据。
5. 报告中的“实际现象”和“协议理论”必须分开表述。
6. 个人信息未知时保留 `【待填写】`，不得编造。

## 4. 统一证据链

每个正式抓包阶段都记录：

- 抓包文件路径。
- 抓包时间。
- 接口名称和接口 GUID，不能只依赖可能变化的接口编号。
- 实际执行命令和目标。
- 捕获过滤器、显示过滤器。
- 文件 SHA-256。
- CSV 路径和行数。
- 采用的关键帧号。
- 截图文件名。
- 验收结果：`PASS`、`WARN` 或 `FAIL`。

正式抓包前重新运行 `tshark -D`，确认 WLAN 仍对应：

```text
\Device\NPF_{887FB422-3CDD-474F-AB19-69DDE6D65A61} (WLAN)
```

接口编号可能在重启、安装驱动或新增网卡后变化，后续优先按接口名称/GUID核对。

## 5. 各阶段实施优化

### 5.1 DHCP

- 执行前关闭或暂停 VPN、代理和虚拟网络客户端，避免网络切换干扰。
- 只针对 WLAN 释放和续租，避免影响虚拟网卡。
- 抓包过滤器 `udp port 67` 可以匹配源端口或目的端口为 67 的 DHCP 流量。
- 抓包开始后再执行释放和续租，续租完成后等待约 3 至 5 秒再停止。
- 若校园网无法形成完整 DORA，优先换手机热点重抓，并在报告中写明真实网络环境。
- Release 可以缺失但必须说明；Discover、Offer、Request、ACK 是核心验收项。

### 5.2 ICMP

- 使用 `ping -4` 强制 IPv4。
- 优先尝试实验指定目标；无响应时依次改用 `114.114.114.114` 和默认网关。
- 最终采用的抓包应至少包含一组真实 Echo Request/Reply。
- CSV 同时保留 `icmp.ident`、`icmp.ident_le`、`icmp.seq`、`icmp.seq_le`，报告明确采用哪种显示形式。

### 5.3 IPv4 分片

- 不设置捕获过滤器，避免漏掉首片或末片。
- 从 `ping -4 -n 1 -l 8000` 开始；目标无响应不影响分片结构验收。
- 若无分片，依次尝试默认网关、`114.114.114.114`、4000 字节、2000 字节。
- 校验分片完整性时不仅检查同一 `ip.id` 有多片，还要检查：
  - 源 IP、目的 IP、协议和 Identification 相同。
  - 至少一片 `MF=1`。
  - 末片 `MF=0` 且 Offset 大于 0。
  - Offset 按 8 字节换算后无重叠、无缺口。
  - 可根据 `ip.len - ip.hdr_len * 4` 校验每片 IP 负载范围。
- 具体 Total Length、Offset、DF、MF 必须使用抓包值，计算只用于校验。

### 5.4 TCP

- Windows 中固定使用 `curl.exe`，避免 PowerShell 别名问题。
- 使用：

```text
curl.exe -4 -v --http1.1 -H "Connection: close" http://example.com/ -o NUL
```

- 若端口 80 被校园网拦截，改用 `http://neverssl.com/`；仍失败则换手机热点。
- curl 完全退出后继续捕获 5 秒，增加捕获完整 FIN 释放过程的概率。
- 只分析同一个 `tcp.stream`。
- 同时导出相对序号和原始序号；报告默认使用 Wireshark 相对序号，并明确说明。
- 出现 RST 可以记录为异常，但不能替代实验要求的正常 FIN 释放过程。

## 6. 自动化脚本要求

### `extract_fields.py`

- 仅使用 Python 标准库。
- 默认定位 `C:\Program Files\Wireshark\tshark.exe`，也支持 `--tshark`。
- 在导出前用 `tshark -G fields` 校验字段是否存在。
- 当前 TShark 4.6.6 已确认使用 `dhcp.*` 字段。
- CSV 使用 UTF-8 编码、逗号分隔、双引号转义。
- 命令失败或 CSV 无数据时返回非零状态，不生成伪成功结果。

### `validate_captures.py`

- 每个协议独立输出 `PASS/WARN/FAIL`。
- DHCP 按事务 ID 和报文类型检查完整 DORA。
- ICMP 按 Identifier、Sequence、反向源/目的地址匹配请求和响应。
- IP 分片按源、目的、协议、Identification 分组并检查覆盖连续性。
- TCP 按 `tcp.stream` 检查三次握手、数据阶段、FIN 释放或 RST。
- 检查关键 Frame Number 在 CSV 中唯一且可回查。
