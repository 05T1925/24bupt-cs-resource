# 阶段 4：IPv4 数据报分片捕获与分析

> 目标：通过发送大尺寸 ICMP 报文触发 IPv4 分片，分析所有分片的包长度、DF、Identification、MF、Fragment Offset。  
> 输入：活跃网卡、ICMP 抓包经验、Wireshark/tshark 可用。  
> 输出：`captures/ip_fragment.pcapng`、`exports/ip_fragment_fields.csv`、IP 分片分析摘要、截图。

---

## 1. 实验目标

本阶段需要构造大于常见以太网 MTU 的 IPv4 数据报，观察其分片传输结构。实验命令建议：

```bat
ping -4 -n 1 -l 8000 www.bupt.edu.cn
```

如目标不响应，可换成：

```bat
ping -4 -n 1 -l 8000 114.114.114.114
```

或：

```bat
ping -4 -n 1 -l 8000 <默认网关IP>
```

---

## 2. IPv4 分片核心字段

报告必须分析：

```text
Total Length：每个分片的 IP 数据报总长度。
Identification：同一个原始 IP 数据报的所有分片具有相同标识。
DF：Don't Fragment，禁止分片标志。
MF：More Fragments，后续还有分片标志。
Fragment Offset：分片偏移量，单位是 8 字节。
Protocol：上层协议，本实验通常为 ICMP，即 Protocol = 1。
```

---

## 3. Wireshark 抓包步骤

1. 打开 Wireshark。
2. 选择活跃网卡。
3. 开始捕获。建议不设置捕获过滤器，避免漏掉相关分片。
4. 打开 CMD。
5. 执行：

```bat
ping -4 -n 1 -l 8000 www.bupt.edu.cn
```

6. 如果失败，改用：

```bat
ping -4 -n 1 -l 8000 114.114.114.114
```

7. 停止捕获。
8. 保存为：

```text
captures/ip_fragment.pcapng
```

---

## 4. Wireshark 显示过滤器

优先使用：

```text
ip.flags.mf == 1 || ip.frag_offset > 0
```

如果没有结果，尝试：

```text
icmp || ip
```

还可以根据目标 IP 过滤：

```text
ip.addr == <目标IP>
```

如果知道某个 Identification 值：

```text
ip.id == 0x实际值
```

## 6. tshark 导出字段命令

```bat
tshark -r captures\ip_fragment.pcapng -Y "ip.flags.mf == 1 || ip.frag_offset > 0" -T fields ^
  -E header=y -E separator=, -E quote=d ^
  -e frame.number ^
  -e frame.time_relative ^
  -e ip.src ^
  -e ip.dst ^
  -e ip.len ^
  -e ip.id ^
  -e ip.flags.df ^
  -e ip.flags.mf ^
  -e ip.frag_offset ^
  -e ip.proto ^
  -e icmp.type ^
  -e icmp.code > exports\ip_fragment_fields.csv
```

如导出为空，尝试导出所有 ICMP 相关 IP 包：

```bat
tshark -r captures\ip_fragment.pcapng -Y "icmp || ip.proto == 1" -T fields ^
  -E header=y -E separator=, -E quote=d ^
  -e frame.number ^
  -e frame.time_relative ^
  -e ip.src ^
  -e ip.dst ^
  -e ip.len ^
  -e ip.id ^
  -e ip.flags.df ^
  -e ip.flags.mf ^
  -e ip.frag_offset ^
  -e ip.proto ^
  -e icmp.type ^
  -e icmp.code > exports\ip_fragment_fields.csv
```

## 7. 分片分组方法

Codex 需要按以下规则识别同一组分片：

```text
同一组分片通常具有：
1. 相同 Source IP。
2. 相同 Destination IP。
3. 相同 Protocol。
4. 相同 Identification。
5. Fragment Offset 不同。
6. 除最后一片外 MF = 1，最后一片 MF = 0。
```

注意：如果 CSV 过滤条件只导出 `MF=1 或 offset>0`，最后一片会被包含，因为最后一片 `offset>0` 且 `MF=0`。

## 9. 理论分析写作要点

报告中可以写：

```text
IPv4 数据报在长度超过链路层 MTU 且 DF 标志不禁止分片时，会被拆分为多个分片传输。每个分片都具有独立的 IPv4 头部，并通过 Identification 字段标识其所属的原始数据报。MF 标志用于说明后续是否还有分片，最后一个分片的 MF 为 0。Fragment Offset 表示当前分片的数据部分在原始 IP 数据报中的偏移，单位为 8 字节。因此，接收端可以根据 Identification、源地址、目的地址、协议号和偏移量重组原始数据报。
```

但是具体字段值必须使用抓包结果，不能用理论推算代替。

## 11. 常见失败处理

### 11.1 没有出现分片

可能原因：

- 目标不可达。
- 网络设备丢弃大包。
- ping 命令没有真正发出。
- 使用的是 IPv6。
- DF 标志或路径 MTU 机制影响。
- Wireshark 抓错网卡。

处理：

```bat
ping -4 -n 1 -l 8000 114.114.114.114
ping -4 -n 1 -l 4000 114.114.114.114
ping -4 -n 1 -l 2000 114.114.114.114
```

从 8000 逐步降低，但报告要记录实际使用命令。

### 11.2 只有一个大包，没有多个分片

可能是网卡卸载功能导致本机抓包看到合并后的包。处理：

1. 尝试抓默认网关方向。
2. 尝试更换网络环境。
3. 尝试在 Wireshark 中关闭协议重组显示影响，但字段仍以实际捕获为准。
4. 必要时临时关闭网卡 Large Send Offload / Checksum Offload，但需要谨慎操作并记录。

### 11.3 ping 无响应但能看到分片

可以接受。实验重点是分片结构，不一定必须收到 Echo Reply。报告中说明目标未响应即可。
