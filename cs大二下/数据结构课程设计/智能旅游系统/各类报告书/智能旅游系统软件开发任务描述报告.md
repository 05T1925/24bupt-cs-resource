## 1. 引言

### 1.1 编写目的

本报告用于描述智能旅游系统课程设计的软件开发任务，包括开发背景、任务来源、目标、范围、技术路线、开发模式、任务分解、阶段过程、成员分工、AI / 智能体辅助过程、算法开发、交付成果、运行验证、风险边界和后续任务，为各专项报告和最终课程设计主报告提供开发任务依据。

本报告侧重回答“本次开发需要完成什么、如何组织实施、产生了哪些成果、如何验证”，不替代功能需求、总体方案或模块详细设计报告。报告结论以当前源码、SQL 和实际运行记录为准，不将早期设想或 AI 生成内容直接视为完成事实。

### 1.2 项目背景

旅游、校园参观和景区游览场景中存在地点信息分散、目的地筛选困难、路线安排复杂、周边餐饮住宿交通查询不便、旅行内容创作成本高等问题。同时，数据结构课程设计要求学生将数据建模、算法设计、复杂度分析和软件工程实现结合，而非仅完成简单 CRUD。

本项目选择智能旅游场景，将地点查询、路线规划、推荐排序、建筑设施、周边服务、美食、旅行日记、小红书热门信息和 AI 旅游助手整合为全栈系统。开发重点是把图与邻接表、Dijkstra、A*、TSP、Haversine、Top-K/Treap、TF-IDF、AC 自动机和 Huffman 编码等结构与算法接入可演示业务。

### 1.3 开发任务来源

开发任务主要来源于：

1. 数据结构课程设计对算法实现、性能分析和应用场景的要求；
2. 旅游用户对地点发现、路线规划、周边查询和旅行记录的实际需求；
3. 前后端分离、分层架构、数据库建模和接口规范等软件工程要求；
4. 将 AI / 智能体用于自然语言交互和辅助开发的探索目标；
5. 课程最终验收所需的源码、可执行环境、测试记录和规范文档。

本报告覆盖开发目标、任务边界、技术栈、开发模式、16 项开发任务、阶段计划、成员分工与贡献、AI 辅助开发、算法性能、交付物、运行测试、风险边界、验收标准及与其他报告的关系。

## 2. 软件开发任务总述

### 2.1 项目一句话描述

本项目是一个面向校园、景区与城市旅游场景的个性化智能旅游系统，由 React 前端、Spring Boot Java 主业务后端、Python FastAPI Agent 服务、MySQL、Redis 和 SQLite 组成。系统围绕地点、建筑、设施、道路、美食、日记、周边、小红书和 Agent 会话等数据，实现查询、推荐、导航、内容管理和自然语言交互。课程设计重点是将路径搜索、推荐排序、文本处理、缓存和 Agent 工具调用用于具体业务，并对性能与能力边界进行分析。

### 2.2 总体开发目标

1. 搭建可在本地完整启动的智能旅游系统；
2. 完成 React、Spring Boot 和 Python Agent 三端协作；
3. 建立 MySQL 业务数据、Redis 缓存及 SQLite Agent 持久化能力；
4. 实现地点、建筑、设施、路线、美食、周边和日记等核心业务；
5. 实现 AI 旅游助手与 AI 辅助写游记；
6. 将课程数据结构和算法接入业务并形成性能分析；
7. 建立构建、测试、健康检查、数据库迁移和运行脚本；
8. 形成可用于验收的源码、数据、文档和问题边界说明。

### 2.3 开发任务边界

本次开发面向课程设计和单机演示，不等同于商业级旅游平台。数据规模、并发、安全、运维和外部平台稳定性均有限；路线依赖已有地点、坐标和路网；小红书依赖 Cookie、平台状态和缓存；图片理解依赖视觉模型 Key、网络和图片可访问性；部分创新能力属于演示级或方案级；测试与 lint 仍有遗留问题。

## 3. 开发环境与技术栈任务

### 3.1 前端开发环境

前端采用 React + Vite，开发端口为 `5173`。任务包括页面路由、API 服务封装、地点和日记卡片、详情页、导航页、周边页、个人中心、AI 助手、SSE 消费、加载与空状态、图片 fallback 和响应式交互。当前生产构建成功；ESLint 仍有 8 个错误和 4 个警告，需要后续修复 Hook、未使用变量和代码规范问题。

### 3.2 Java 后端开发环境

后端采用 Spring Boot 3.3.5，项目目标为 Java 17，当前在 Java 21 环境完成运行与测试。主要技术包括 MyBatis-Plus、Spring Security、JWT、Flyway、Swagger、Redis、统一 `Result<T>`、全局异常处理以及 Controller—Service—Mapper—Entity 分层。服务端口为 `8080`。当前 132 项测试中 126 项通过，6 项因旧状态码期望和 H2 Schema 漂移等原因失败。

### 3.3 Python Agent 开发环境

Agent 使用 Python FastAPI，端口 `9000`。任务包括 Dispatcher、Orchestrator、ChatAgent、DiscoverAgent、RouteAgent、DiaryAgent、ToolRegistry、文本 LLM、可选视觉模型、SQLite 会话和任务、出游搭子、偏好、SSE 事件以及调用 Java REST API 的 `tourism_api`。编排框架已实现，但搜索、美食、路线和最近设施等工具参数与 Java 合同仍需进一步统一。

### 3.4 数据库、缓存与文件环境

MySQL 运行于 `127.0.0.1:3306`，保存业务数据；Redis 运行于 `127.0.0.1:6379`，主要用于 XHS 缓存和发布限流；SQLite 保存 Agent 会话、消息、搭子、任务和偏好；`uploads` 保存图片、视频文件及 GIF 输出。数据库初始化、周边数据导入、Flyway 迁移、H2 测试 Schema 和数据质量检查均属于开发任务。

### 3.5 外部依赖与配置

OpenAI Key 采用已有环境变量复用，没有明文写入项目。文本模型负责理解和生成，DeepSeek 等文本模型不承担图片理解；视觉能力需视觉模型 Key、网络和可访问图片。小红书依赖 Cookie、外部平台和账号状态；地图能力可依赖可选 Provider。所有密钥和 Cookie 均应通过环境变量或安全配置管理。

## 4. 软件开发模式与组织方式

### 4.1 开发模式

项目采用前后端分离和“双后端职责分工”：Java 负责鉴权、确定性业务、数据库和算法，Python 负责 LLM 与 Agent 编排。开发过程以数据库和接口为基础，页面适配与接口开发并行，通过周报式迭代、Bug 分析、Fix Plan 和 Root Cause 文档推动修复，并使用 AI 辅助但坚持人工核验。

### 4.2 软件工程过程

1. 根据课程要求和旅游场景识别需求；
2. 建立业务表、关系、索引和种子数据；
3. 开发 Java 分层接口与统一返回结构；
4. 开发 React 页面并完成 API 适配；
5. 实现并接入图、推荐和文本算法；
6. 集成 Python Agent、LLM、ToolRegistry 和 SSE；
7. 导入周边及扩展数据并治理质量；
8. 建立测试、构建、迁移和健康检查；
9. 依据日志和失败项完成根因分析与迭代；
10. 整理事实底稿、专项报告和验收材料。

### 4.3 AI / 智能体辅助开发模式

AI 用于阅读项目材料、归纳架构、辅助生成 Controller/Service/页面/SQL/测试、比较算法、定位路线合同、周边乱码、图片重复、AI 日记和 XHS 问题，并生成文档初稿。所有 AI 产出必须经过人工代码审查、SQL 核对、构建、测试和运行验证；AI 不能独立证明功能完成或外部平台稳定。

### 4.4 开发文档管理

项目材料包括 README、Week 5—15 开发日志、Bug 分析、Fix Plan、Root Cause、实现与优化方案、统一事实底稿、自评表、验收指导稿及八类专项报告。早期文档只代表当时状态，最终报告以当前源码和实跑结果纠偏，避免将最终成果倒推到早期阶段。

## 5. 软件开发任务分解

### 5.1 T-01 数据库与数据模型开发

- **目标：** 建立地点、路线、用户、内容、周边和外部增强功能的数据底座。
- **内容：** 设计 `sys_user`、`spot_place`、`spot_building`、`spot_facility`、`spot_road_edge`、`spot_food`、`travel_diary`、`user_behavior`、`spot_surrounding`、`spot_xhs_info`、`user_xhs_account`、`xhs_publish_log`；编写 schema、种子、周边脚本和 Flyway；建立 H2 测试数据。
- **结构：** 主键和索引、JSON 字段、软删除、时间字段、道路边表、分页结构。
- **成果：** MySQL 初始化和 Flyway 已成功，基础数据可支撑系统运行。
- **状态与边界：** 核心模型完成；H2 缺少部分 XHS 表和日记字段，需同步。
- **验收：** 执行 SQL/Flyway、查询表和行数、启动后端。

### 5.2 T-02 用户认证与安全开发

- **目标：** 为用户数据和个性化操作建立身份上下文。
- **内容：** 注册、登录、BCrypt、JWT、Security Filter、公开/受保护接口、当前用户和统一异常。
- **成果：** 认证主链路已形成，Java Agent 代理可从 Principal 获取用户。
- **边界：** 错误 HTTP 状态码与旧测试期望不一致；日记 POST 和 XHS 等公开范围需复核；安全权限体系仍需完善。
- **验收：** 页面登录、Swagger、JWT 请求、认证集成测试。

### 5.3 T-03 地点浏览、搜索与详情开发

- **目标：** 满足用户快速查找、筛选和了解目的地的需求。
- **内容：** 地点分页、类型和关键词筛选、热门/高评分排序、详情、图片和标签、建筑设施及可选 XHS 聚合。
- **数据与技术：** `spot_place`、`spot_building`、`spot_facility`、`spot_xhs_info`；`Page<T>`、MyBatis-Plus Wrapper、LIKE、JSON 解析和排序。
- **成果：** 首页、搜索、详情与 Java 接口形成核心闭环。
- **边界：** 数据库不存在的地点不能返回；XHS 聚合失败应降级。
- **验收：** 页面、REST、数据库查询和空结果测试。

### 5.4 T-04 推荐与排序开发

- **目标：** 根据兴趣、行为、标签和热度减少用户选择成本。
- **内容：** 地点推荐、热门/评分排行、行为推荐、日记推荐和空结果回退。
- **算法：** 余弦相似度、Jaccard、协同过滤、TF-IDF、热度分、Top-K 和 Treap。
- **性能：** 小候选直接排序为 `O(n log n)`；扩大后可用 Top-K 将维护成本控制为平均 `O(n log k)`；稀疏向量单候选相似度约 `O(d)`。
- **成果：** 课程设计级混合推荐和算法测试。
- **边界：** 行为和标签稀疏限制效果，不能表述为工业级推荐。

### 5.5 T-05 建筑与设施查询开发

- **目标：** 帮助用户了解地点内部建筑和服务设施。
- **内容：** 按地点查询建筑和设施、按类型筛选、详情聚合和空状态。
- **数据：** 建筑约 63 条、设施约 204 条。
- **成果：** 查询接口与地点详情、导航链路已贯通。
- **验收：** REST、页面详情和数据库关联查询。

### 5.6 T-06 附近设施与 LBS 开发

- **目标：** 根据用户位置查找附近服务并按距离排序。
- **内容：** 经纬度、半径、类型输入；附近筛选；直线距离与路网距离；失败回退。
- **算法：** Haversine 单次 `O(1)`；候选扫描 `O(n)`、排序 `O(n log n)`；Dijkstra 可计算可达路径。
- **成果：** 课程规模下基本可用。
- **边界：** 精度依赖坐标和路网；大规模需空间索引或数据库 GIS。

### 5.7 T-07 路线规划与导航开发

- **目标：** 支持校园/景区单目标、多目标、室内和室内外路线安排。
- **内容：** 路网构图、最短距离/时间、多点顺序、节点和分段返回、室内 JSON、入口衔接及 Agent 路线入口。
- **数据：** `spot_road_edge` 约 483 条，地点/建筑/设施坐标，`indoor_navigation.json`。
- **算法：** 邻接表空间 `O(V+E)`；Dijkstra `O((V+E)logV)`；A* 用 Haversine 启发；TSP DP 为 `O(n²2ⁿ)`，目标较多时使用启发式。
- **成果：** 算法和接口真实存在。
- **边界：** 效果依赖节点、坐标、路网和 Provider；Agent—Java 路线参数合同仍需加强，仅说明已覆盖数据范围内的路线能力。

### 5.8 T-08 美食查询开发

- **目标：** 满足用户按地点、菜系和热度查找餐饮的需求。
- **内容：** 列表、菜系筛选、热门、详情、地点关联和 Agent 工具。
- **数据与算法：** `spot_food` 约 40 条；条件查询、模糊匹配、排序和 Top-K。
- **成果：** 基础查询完成。
- **边界：** 餐厅领域建模和数据覆盖有限；Agent 对返回分页字段的理解需统一。

### 5.9 T-09 旅行日记开发

- **目标：** 支持旅行记录、媒体展示、搜索、评价和内容处理。
- **内容：** 日记列表、详情、创建、编辑、删除、搜索、推荐、评分、点赞、图片、视频和标签。
- **数据与算法：** `travel_diary` 约 14 条种子、`user_behavior`；`Page<T>`、AC 自动机和 Huffman。
- **性能：** AC 多模式匹配 `O(L+z)`；Huffman 构树约 `O(σlogσ)`、编解码 `O(L)`。
- **成果：** 业务代码形成核心闭环。
- **边界：** H2 Schema 漂移导致日记相关测试失败，需同步生产字段。

### 5.10 T-10 AI 辅助写游记开发

- **目标：** 降低用户整理旅行素材和创作日记的成本。
- **内容：** 文本/图片素材、意图识别、风格确认、标题正文标签生成、卡片展示、图片聚合、人工编辑和保存。
- **技术：** DiaryAgent、ChatAgent、`model_router`、`llm_client`、SSE、前端日记弹窗和 Java 日记接口。
- **成果：** 文本生成和确认发布链基本可用。
- **边界：** DeepSeek 等文本模型不理解图片；视觉模型依赖 Key、网络和图片可访问性；AI 内容必须人工确认。

### 5.11 T-11 校园与景区周边开发

- **目标：** 满足到达地点后的餐饮、购物、娱乐、酒店、交通和服务查询。
- **内容：** 周边表、分页、地点和类别筛选、详情、距离、评分、人均、标签和降级。
- **数据与算法：** `spot_surrounding`；Haversine、分类统计、分页和条件查询。
- **成果：** 周边页面与接口已形成。
- **边界：** 北邮 POI 相对可靠；景区批量数据存在模板化、编码、重复和真实性风险。

### 5.12 T-12 小红书热门打卡地与同步开发

- **目标：** 为用户提供外部内容热度、热门笔记和发布状态参考。

## 9. 算法开发任务与性能分析

| 算法 / 结构 | 对应任务 | 输入 → 输出 | 开发目标与选择依据 | 复杂度 / 性能 | 接入状态与边界 |
|---|---|---|---|---|---|
| 图 / 邻接表 | T-07 | 道路边、节点 → 图 | 稀疏路网节省空间、便于遍历 | 空间 `O(V+E)` | 路线核心；依赖覆盖 |
| Dijkstra | T-06/T-07 | 起点、非负图 → 最短路径 | 稳定求最短距离/时间 | `O((V+E)logV)` | 核心业务 |
| A* | T-07 | 起终点 → 目标路径 | 利用 Haversine 减少目标搜索 | 最坏近 Dijkstra | 核心业务，坐标影响启发 |
| TSP | T-07 | 起点、目标集 → 访问顺序 | 小规模多景点顺序优化 | DP `O(n²2ⁿ)` | 增强；大规模用启发式 |
| Haversine | T-06/T-11 | 两经纬度 → 距离 | 无路网时快速估算 | 单次 `O(1)`，扫描 `O(n)` | 已接入；非道路距离 |
| Top-K / Treap | T-04/T-08 | 分数流 → 前 K | 避免大候选全量排序 | 平均 `O(n log k)` | 课程核心结构 |
| TF-IDF | T-04/T-09 | 查询、文本 → 排序 | 课程规模文本检索 | 约 `O(ND)` | 限定检索场景 |
| 余弦 / 协同过滤 | T-04 | 特征/行为 → 推荐 | 内容与行为混合推荐 | 余弦单候选 `O(D)` | 课程级，行为稀疏 |
| AC 自动机 | T-09 | 词库、正文 → 命中 | 多敏感词一次扫描 | `O(L+z)` | 已接入日记 |
| Huffman | T-09 | 正文 → 编码/原文 | 展示前缀编码和压缩 | 构树 `O(σlogσ)` | 课程级业务封装 |
| JSON 字段 | T-01/T-09 | 数组对象 ↔ 字符串 | 灵活保存标签和媒体 | 与字段长度线性相关 | 需校验格式 |
| `Page<T>` | T-03/T-09/T-11 | 页参数 → 分页结果 | 控制查询和传输规模 | 依 SQL 与索引 | 广泛接入 |
| MyBatis Wrapper | 多任务 | 动态条件 → SQL | 统一筛选排序 | 依执行计划 | 工程结构 |
| JWT | T-02 | 凭据 → Token → 用户 | 无状态鉴权 | 与 Token 长度近线性 | 主链路，安全需加固 |
| ToolRegistry | T-13 | 名称/参数 → 工具结果 | 动态注册、隔离和调用 | 平均查找 `O(1)` | Agent 核心 |
| SSE | T-10/T-13 | 事件 → 增量 UI | 降低首字等待 | 与事件数线性 | 已接入 |
| Redis | T-12 | 外部数据 → 缓存 | 减少平台重复访问 | 命中近 `O(1)` | XHS 增强依赖 |
| Fibonacci Heap | 算法扩展 | 键值 → 堆操作 | 展示摊还复杂度优势 | 插入摊还 `O(1)` 等 | 有实现测试，非主路线堆 |

## 15. 总结

本次软件开发任务围绕智能旅游系统展开，形成了由 React、Spring Boot、Python FastAPI Agent、MySQL、Redis、SQLite 和本地文件存储组成的多服务工程结构。王博生主责前后端开发、接口联调和项目仓库管理；刘文涛主责数据库实现与维护、算法实现与分析及实验报告撰写；胡文龙主责 Agent 全流程开发接入、AI 功能落地和前端美化。三位成员在系统集成、测试验证、问题修复和验收材料整理阶段共同协作。

项目将图和邻接表、Dijkstra、A*、TSP、Haversine、Top-K/Treap、TF-IDF、余弦相似度、AC 自动机和 Huffman 等用于路线、推荐、检索和日记业务，体现了数据结构课程设计特色。大模型与智能体在需求分析、架构讨论、编码、算法比较、问题定位、测试和文档整理中发挥辅助作用，但所有结论均需人工通过源码、SQL 和运行结果核验。

目前核心功能具备课程演示和最终材料提交基础，三端健康检查通过，前端构建、MySQL/Flyway 和 Redis 验证成功；同时仍存在后端测试 6 项失败、XHS 4 项失败、前端 lint、H2 Schema、跨服务合同、数据质量、外部平台、多模态和权限边界等后续任务。本报告为功能需求、总体方案、数据结构、模块设计、测试、评价改进、用户说明和课程设计主报告提供统一的开发任务背景。
